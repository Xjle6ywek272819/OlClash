<h1 align="center">OlcLash</h1>

OlcLash is an experimental Android VPN client that supports two different
subscription and transport families in one application:

- standard Mihomo YAML subscriptions, including configurations generated by Remnawave;
- OLCWave subscriptions containing `olcrtc://` endpoints.

The project is based on [ClashFest](https://github.com/Nemu-x/ClashFest) and is
currently intended for testing. It is not affiliated with Remnawave, ClashFest,
olcbox, Mihomo, or any VPN provider.

## How profile switching works

| Active profile | Data path | Routing policy | Per-app VPN |
| --- | --- | --- | --- |
| Mihomo / Remnawave | Android TUN → Mihomo → selected proxy | Profile plus the user's local overlay | The saved allow/block-list is applied |
| OLCWave | Android TUN → Mihomo gVisor adapter → loopback SOCKS5 → olcRTC → OLC server | The OLC server is authoritative; the local adapter uses `MATCH` | All applications enter the VPN; OlcLash itself is excluded to prevent a carrier loop |

The stack selected in Settings continues to apply to normal Mihomo profiles.
OLCWave profiles use gVisor internally because Mihomo's Android `system` stack
does not work reliably as a TUN-to-loopback-SOCKS adapter for this transport.
Switching profile type does not overwrite the user's saved Mihomo routing or
per-app settings.

See [Architecture](docs/ARCHITECTURE.md) for implementation details and trust boundaries.

## Current status

- Importing and updating Mihomo/Remnawave subscriptions works.
- Importing OLCWave subscriptions works.
- The transport is selected automatically from the active profile.
- OLCWave traffic is carried by the pinned olcRTC Android runtime.
- CI publishes a single `arm64-v8a` debug APK artifact.

OLCWave support is new. Reconnection, traffic accounting, latency presentation,
and OLC-specific UI still need polish.

## Installing a CI build

1. Open the repository's **Actions** tab.
2. Select **Android CI** and a successful run on `main`.
3. Download `olclash-alpha-arm64-apk` from **Artifacts**.
4. Extract the archive and install the ARM64 APK.

The current package name is `com.vibecode.olclash`. Only 64-bit ARM Android
devices are supported by the bundled olcRTC runtime.

## Building

Requirements:

- JDK 21;
- Android SDK and the project-compatible NDK;
- Git submodules;
- network access to the pinned olcbox release during the build.

Clone recursively, then build the Alpha debug variant:

```bash
git clone --recursive https://github.com/Xjle6ywek272819/OlClash.git
cd OlClash
./gradlew assembleAlphaDebug
```

On Windows:

```powershell
git clone --recursive https://github.com/Xjle6ywek272819/OlClash.git
cd OlClash
.\gradlew.bat assembleAlphaDebug
```

The build script downloads one pinned official olcbox APK, verifies its SHA-256,
and extracts the ARM64 `libgojni.so`. Exact provenance is documented in
[OLCRTC_PROVENANCE.md](docs/OLCRTC_PROVENANCE.md). No subscription URL, access
token, HWID, or signing key is stored in this repository.

## Repository layout

| Path | Purpose |
| --- | --- |
| `app/` | Android entry points, profile UI, and package assembly |
| `service/` | VPN service, profile processing, routing, and olcRTC lifecycle |
| `core/` | JNI bridge and Mihomo core integration |
| `common/` | Shared models and subscription parsing |
| `design/` | Views, resources, themes, and settings UI |
| `.github/scripts/fetch-olcrtc-android.sh` | Reproducible retrieval of the pinned olcRTC runtime |

## Security notes

- The olcRTC SOCKS endpoint listens only on `127.0.0.1`.
- OLC carrier sockets run in a separate process bound to a physical non-VPN network.
- Imported Mihomo profiles pass through ClashFest's configuration hardening pipeline.
- OLCWave subscription bodies contain connection credentials. Do not include real
  subscription bodies or URLs in issues and logs.

Please report bugs with credentials, room identifiers, subscription URLs, and
device identifiers removed.
